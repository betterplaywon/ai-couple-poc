# AI 연인 프로토타입 — `.claude/` + `docs/` 개발 인프라 구축

## Context

`ai-couple-poc`는 현재 커밋 0개의 Vite 8 + React 19 + TS 6 스캐폴드다. `.claude/`도 `docs/`도 없다.

이 작업의 산출물은 **앱이 아니라 앱을 만들 개발 환경**이다. 과제의 출제 의도가 "AI로 대부분의 코드를 빠르게 짜면서 복잡성과 리스크를 어떻게 관리하는가"이므로, `.claude/`와 `docs/`는 부수적 문서가 아니라 **평가 대상 그 자체**다. 따라서 장식용 문서를 늘리지 않고, 실제로 매 세션 동작하는 최소 장치만 만든다.

확정된 전제:
- **컨셉**: 관계 서사형 — 첫 만남부터 연애까지 챕터가 진행되는 채팅 AI 연인
- **스택**: 현행 Vite SPA 유지 + `/api` Vercel 서버리스 함수로 Claude API 프록시
- **기한**: 2~3일 → 스코프 판정 장치가 문서보다 우선

### 설계 원칙 (왜 이런 구조인가)

1. **rules는 CLAUDE.md가 `@`로 임포트해야 로드된다.** Claude Code에 `.claude/rules/`를 자동으로 읽는 기능은 없다. 파일만 두면 죽은 문서가 되므로 CLAUDE.md를 진입점으로 삼는다.
2. **docs는 "결정의 로그", CLAUDE.md는 "항상 지킬 규칙".** 둘을 섞으면 컨텍스트가 비대해져 오히려 지시 준수율이 떨어진다. 규칙은 짧게, 서사는 docs로 뺀다.
3. **에이전트는 "코드 짜는 나"와 이해가 충돌하는 역할에만 만든다.** 구현자와 같은 관점의 에이전트는 만들지 않는다.

## 2. `.claude/rules/` — 항상 로드되는 규칙 (각 30~60줄)

### `00-product.md` — 제품 원칙
컨셉의 불변식. 구현 중 흔들리면 안 되는 것들:
- **호감도 숫자를 UI에 노출하지 않는다.** 게이지를 보여주는 순간 로맨스가 육성 게임이 된다. 상태는 *말투, 답장 텀, 이모지 빈도, 호칭, 프로필 채도*로만 드러낸다. ← 이 프로젝트 감수성의 핵심
- **되돌릴 수 없는 순간을 만든다.** 고백 씬은 1회, 세이브/로드·되감기 없음
- **AI가 기억한다.** 유저가 흘린 사실이 다음 챕터에서 되돌아와야 함
- 캐릭터는 항상 대기 중인 하인이 아니다 — 삐치고, 늦게 답하고, 자기 얘기를 한다

### `10-engineering.md` — 복잡도 예산
AI가 코드를 대량 생산할 때의 실제 실패 모드를 막는 수치화된 상한:
- 의존성 추가는 rules 위반 아님 → 단, `docs/03-tradeoffs.md`에 1줄 근거 필수
- **추상화는 3번째 중복부터.** 2번까지는 복붙 유지
- 파일당 200줄, 컴포넌트당 props 7개 상한. 넘으면 분리 아니라 *기능 축소*를 먼저 검토
- 서버리스 함수는 `api/` 아래 3개 이하로 유지
- 테스트는 쓰지 않는다. 대신 `dialogue-replay` 스킬로 시나리오 회귀를 잡는다 (기한상 명시적 타협)
- 죽은 코드 즉시 삭제 — 주석 처리 금지

### `20-ai-safety.md` — 로맨스 도메인 가드레일
"연인 서비스"를 만들면서 반드시 선을 그어야 하는 것:
- 캐릭터 설정 연령 명시(성인), 미성년 암시 표현 금지
- 성적 묘사 수위 상한을 프롬프트에 하드코딩, 유저 요청으로 우회 불가
- **위기 신호 감지 시 캐릭터를 유지한 채 실제 도움을 안내한다** — 몰입을 위해 방치하지 않고, 그렇다고 로봇처럼 캐릭터를 깨지도 않는 문구를 사전 작성
- "너 AI지?" → 부정하지 않되 캐릭터를 버리지도 않는 응답 정책. 앱 하단에 AI 고지 상시 노출
- 프롬프트 인젝션으로 캐릭터가 붕괴되면 버그로 취급

### `30-scope.md` — 기한 규칙
- D-Day 기준 남은 시간과 "지금 데모 가능한가"를 매 작업 전 자문
- **플레이 가능성 > 완성도 > 코드 품질** 순으로 타협
- 새 아이디어는 즉시 `docs/06-scope.md`의 Won't 섹션으로. 구현하지 않고 기록만
- 막히면 15분 룰: 15분 내 안 풀리면 우회 경로 또는 기능 삭제

## 3. `.claude/agents/` — 3개

구현자와 **이해가 충돌하는** 역할만.

### `romance-director.md`
- 역할: 페르소나 카드, 챕터별 시스템 프롬프트, 실제 대사 톤을 쓰고 감수. 코드는 건드리지 않음
- 왜 분리: 구현 모드일 때는 "동작하는가"만 보게 되어 대사가 밋밋해진다. 문학적 판단을 하는 별도 컨텍스트가 필요
- tools: Read, Write, Edit (`docs/`, `src/persona/` 한정), Grep
- model: opus

### `scope-guard.md`
- 역할: "이 기능 지금 해야 하나"를 판정. 남은 기한 대비 스코프 심판. 판정 결과를 `docs/03-tradeoffs.md`와 `docs/06-scope.md`에 기록
- 왜 분리: 구현자는 항상 "이것만 더 하면"이라고 말한다. 자를 권한을 가진 별도 관점이 필요
- tools: Read, Grep, Glob, Edit(`docs/`만)
- model: sonnet

### `character-qa.md`
- 역할: 실제로 대화를 돌려 캐릭터 붕괴·챕터 오전환·톤 회귀를 찾는다. 코드 리뷰가 아니라 *체험 리뷰*
- 왜 분리: 자기가 짠 프롬프트는 자기가 검증 못 한다
- tools: Bash, Read, Grep
- model: sonnet

# 회귀 로맨스 PoC — `.claude/` + `docs/` 개발 인프라 구축

## Context

`ai-couple-poc`는 커밋 0개의 Vite 8 + React 19 + TS 6 스캐폴드다. `.claude/`도 `docs/`도 없다.

이 작업의 산출물은 **앱이 아니라 앱을 만들 개발 환경**이다. 과제 출제 의도가 "AI로 대부분의 코드를 빠르게 짜면서 복잡성과 리스크를 어떻게 관리하는가"이므로 `.claude/`와 `docs/`는 부수 문서가 아니라 평가 대상 그 자체다. 따라서 장식용 문서를 만들지 않고, 매 세션 실제로 동작하는 최소 장치만 만든다.

### 검증할 가설 (단 하나)

> **끝이 있는 유한 서사가 무한 채팅보다 몰입과 완주를 만든다.**

이 문장이 모든 판단의 기준선이다. 어떤 기능이 이 가설 검증에 기여하지 않으면 만들지 않는다.

### 확정된 제품 정의

**완결형 3화 로맨스 회귀물.** 3화를 완주하면 엔딩이 나오고, 배드엔딩이면 1화로 회귀한다.

| 축 | 결정 |
|---|---|
| 분량 | 3화 × 화당 6~8턴, 1회차 완주 ~20분 |
| 엔딩 | 배드(회귀) / 노말(미지근) / 트루(연인) — 3개 |
| 회귀 | 배드엔딩 시 1화로 회귀, **회차가 쌓일수록 AI가 각성** |
| 회차 각성 | 1회차 완전 리셋 → 2회차 미묘한 기시감 → 3회차 자각("또 왔구나") |
| 호감도 | **화면에 게이지로 노출** — 5초 안에 일반 챗봇과 다름이 보여야 함 |
| 캐릭터 | 1명. 항상 다정하지 않다. 삐치고 거절한다 |

**회귀물을 고른 이유**: 배드엔딩이 게임오버가 아니라 서사 장치가 된다. 심사자가 여러 엔딩을 자연스럽게 돌려보게 되고, 프로토타입의 짧은 분량이 결함이 아니라 의도가 된다.

### 스택

현행 Vite SPA 유지 + `api/chat.ts` 서버리스 함수 1개(Claude API 키 보호 목적). 상태는 **React 메모리만** — localStorage도 쓰지 않는다. 새로고침 = 처음부터, 이것도 회귀다.

### PoC에서 만들지 않는 것 (하드 제외)

회원가입 · 로그인 · DB · 배포 인프라 작업 · 결제 · TTS/음성 · 이미지 생성 · 캐릭터 2명 이상 · 대화 저장/불러오기.

이 목록은 `.claude/rules/30-scope.md`에 그대로 박아 세션 중 표류를 막는다.

## 핵심 설계: 상태 기반 대화 엔진

매 턴 모델은 대사만 뱉지 않고 구조화 출력을 반환한다.

```json
{
  "dialogue": "...",
  "affection_delta": -2,
  "emotion": "서운함",
  "scene_advance": false
}
```

### 여기서 한 가지 수정 제안

**`scene_advance`의 최종 결정권은 서버가 갖는다.** LLM은 "지금 화가 마무리될 분위기"라는 *신호*만 주고, 실제 화 전환은 서버가 `턴 수 + 호감도 임계값`으로 판정한다.

근거: LLM에게 진행 제어권을 주면 3턴 만에 3화로 날아가거나 12턴째도 안 넘어간다. 완주율·평균 턴 수 같은 지표를 뽑으려면 진행 규칙이 결정론적이어야 한다. LLM은 연기를 하고, 상태 전이는 코드가 한다.

이 원칙을 `docs/02-state-engine.md`와 `10-engineering.md`에 명시한다.

## 2. `.claude/rules/` — 항상 로드 (각 30~60줄)

### `00-product.md` — 제품 불변식
- 가설 한 문장을 맨 위에
- **리스크가 핵심 변수다.** 서툶·감점·배드엔딩·회귀는 같은 변수의 장치이며 하나라도 무디면 가설 검증이 실패한다
- **웃기되 비웃지 않는다.** 모태솔로를 희화화하면 코미디가 되고 애착이 죽는다. 서툶은 개그가 아니라 긴장으로 읽혀야 한다
- **감정 노동을 시키지 않는다.** 유저가 받아주기만 하면 지친다 — 화마다 최소 1회, 서툰 사람이 용기를 내는 순간을 보상으로 배치한다
- **서툶은 진화한다.** 1화 회피 → 2화 과잉 노력 → 3화 직진. 같은 종류의 어색함을 반복하면 3화를 못 버틴다
- **유한하다.** 3화 6~8턴 완결. "조금만 더 대화" 유혹을 거절한다
- **호감도는 보인다.** 게이지·화 표시·감정 라벨을 UI에 노출한다
- **AI는 항상 다정하지 않다.** 감점이 실제로 발생해야 게이지가 의미를 가진다
- 진행 제어는 코드, 연기는 LLM

### `10-engineering.md` — 복잡도 예산

### 검증할 가설 (단 하나)

> **애착은 다정함이 아니라 리스크에서 나온다 — 서툴러서 실패할 수 있는 상대가, 항상 완벽하게 다정한 AI보다 깊은 몰입을 만든다.**

### 모태솔로 설정을 택한 이유 (엔지니어링 근거)

모든 AI 연인 서비스의 실제 약점은 AI가 연애를 못 한다는 것이다 — 뻣뻣하고, 과하게 순응적이고, 맥락을 못 읽고, 답이 너무 빠르다. 유저는 즉각 알아채고 몰입이 깨진다.

캐릭터가 설정상 모태솔로면 **그 실패 모드 전부가 캐릭터에 맞는 행동이 된다.** 2~3일 프로토타입에서 프롬프트 품질이 완벽할 수 없다는 걸 감안한 리스크 흡수 장치다. 동시에 최대 리스크였던 **아첨 편향**도 해소된다 — 모태솔로는 어색해서 물러서고 신호를 오독할 *이유*가 있으므로 감점이 캐릭터와 일관되게 나온다.

### 확정된 제품 정의

| 축 | 결정 |
|---|---|
| 캐릭터 | 남자 모태솔로 1명. **담백하고 진지한** 서툶 (말을 못 하는 게 아니라 고르다가 달아난다) |
| 분량 | 3화 × 화당 6~8턴, 1회차 완주 ~20분 |
| 엔딩 | 배드(회귀) / 노말(미지근) / 트루(연인) — 3개 |
| 회귀 | 배드엔딩 시 1화로 회귀, 회차가 쌓일수록 각성 |
| 회차 각성 | 1회차 리셋 → 2회차 기시감 → 3회차 자각. **기억이 아니라 "몸에 남은 익숙함"으로 표현** — 회차별 서툶 레벨 파라미터(100% → 85% → 70%)가 각성의 증거가 된다 |
| 호감도 | 화면에 게이지로 노출 — 5초 안에 일반 챗봇과 다름이 보여야 함 |

### 스택

현행 Vite SPA 유지 + `api/chat.ts` 서버리스 함수 1개(Claude API 키 보호). 상태는 **React 메모리만** — localStorage도 쓰지 않는다. 새로고침 = 처음부터, 이것도 회귀다.

### 하드 제외

회원가입 · 로그인 · DB · 배포 인프라 작업 · 결제 · TTS/음성 · 이미지 생성 · 캐릭터 2명 이상 · 대화 저장/불러오기.

`.claude/rules/30-scope.md`에 그대로 박아 세션 중 표류를 막는다.

### 성공 지표

**배드엔딩 후 재도전률**이 가설의 직접 증거다 — 잃은 뒤에 다시 오는가. 보조로 완주율, 엔딩 분포, 평균 턴 수, 트루엔딩 도달 회차 수.

## 핵심 설계: 상태 기반 대화 엔진

매 턴 모델은 대사만 뱉지 않고 구조화 출력을 반환한다.

```json
{
  "dialogue": "...",
  "affection_delta": -2,
  "emotion": "서운함",
  "scene_advance": false
}
```

### 수정 제안 한 가지

**`scene_advance`의 최종 결정권은 서버가 갖는다.** LLM은 "화가 마무리될 분위기"라는 *신호*만 주고, 실제 전환은 서버가 `턴 수 + 호감도 임계값`으로 판정한다.

근거: LLM에 진행 제어권을 주면 3턴 만에 3화로 날아가거나 12턴째도 안 끝난다. 완주율·평균 턴 수를 지표로 쓰려면 진행 규칙이 결정론적이어야 한다. **LLM은 연기를 하고, 상태 전이는 코드가 한다.**

## 2. `.claude/rules/` — 항상 로드 (각 30~60줄)

### `00-product.md` — 제품 불변식
- 가설 한 문장을 맨 위에
- **리스크가 핵심 변수다.** 서툶·감점·배드엔딩·회귀는 같은 변수의 장치이며 하나라도 무디면 가설 검증이 실패한다
- **웃기되 비웃지 않는다.** 모태솔로를 희화화하면 코미디가 되고 애착이 죽는다. 서툶은 개그가 아니라 긴장으로 읽혀야 한다
- **감정 노동을 시키지 않는다.** 유저가 받아주기만 하면 지친다 — 화마다 최소 1회, 서툰 사람이 용기를 내는 순간을 보상으로 배치한다
- **서툶은 진화한다.** 1화 회피 → 2화 과잉 노력 → 3화 직진. 같은 종류의 어색함을 반복하면 3화를 못 버틴다
- **유한하다.** 3화 6~8턴 완결. "조금만 더 대화" 유혹을 거절한다
- **호감도는 보인다.** 게이지·화 표시·감정 라벨을 UI에 노출한다
- **AI는 항상 다정하지 않다.** 감점이 실제로 발생해야 게이지가 의미를 가진다
- 진행 제어는 코드, 연기는 LLM

### `10-engineering.md` — 복잡도 예산
- **상태 전이 로직은 한 곳에만.** 호감도·화·엔딩 판정을 클라와 서버 양쪽에 두지 않는다
- 추상화는 3번째 중복부터. 2번까지는 복붙
- 파일당 200줄, `api/` 함수 1개 상한
- 의존성 추가는 `docs/03-tradeoffs.md`에 1줄 근거 필수
- **테스트 코드를 쓰지 않는다.** `playthrough` 스킬의 자동 완주 시뮬레이션으로 회귀를 잡는다 (명시적 타협)
- 죽은 코드 즉시 삭제, 주석 처리 금지

### `20-ai-safety.md` — 로맨스 가드레일
- 캐릭터 성인 설정 명시, 미성년 암시 표현 금지
- 성적 묘사 수위 상한을 프롬프트에 고정, 유저 요청으로 우회 불가
- 위기 신호 감지 시 캐릭터를 깨지 않으면서 실제 도움을 안내하는 문구 사전 작성
- "너 AI지?" → 부정하지 않되 캐릭터도 버리지 않음. 화면 하단 AI 고지 상시 노출
- 프롬프트 인젝션에 의한 캐릭터 붕괴는 버그로 취급

### `30-scope.md` — 기한과 제외
- 하드 제외 목록을 그대로 나열
- **플레이 가능성 > 완주 가능성 > 코드 품질** 순으로 타협

기능 하나를 추가할지 고민될 때는 "이게 이 가설 검증에 기여하는가"만 묻는다. 아니면 만들지 않는다.

# 제품 불변식

> **애착은 다정함이 아니라 리스크에서 나온다.**
> 서툴러서 실패할 수 있는 상대가, 항상 완벽하게 다정한 AI보다 깊은 몰입을 만든다.

## 리스크가 핵심 변수다

모태솔로의 서툶 · 호감도 감점 · 배드엔딩 · 회귀는 **전부 같은 변수(리스크)의 장치**다.
하나라도 무뎌지면 나머지가 멀쩡해도 가설 검증은 실패한다.

"이 변경이 리스크를 키우는가 줄이는가"를 먼저 묻는다. 줄인다면 대개 하지 말아야 할 변경이다.

## 캐릭터

**남자 모태솔로 1명.** 담백하고 진지한 서툶.

- 말을 못 하는 게 아니라 **고르다가 달아난다**. 침묵과 말 끊김이 주된 표현 수단
- 감탄사 남발, 오버 리액션, 이모지 도배는 이 캐릭터가 아니다

### 웃기되 비웃지 않는다

모태솔로를 희화화하는 순간 로맨스가 코미디가 되고 애착이 죽는다.
서툶은 **개그가 아니라 긴장**으로 읽혀야 한다. 유저가 웃더라도 그건 안쓰러움에서 나온 웃음이어야 한다.

### 서툶은 진화한다

같은 종류의 어색함을 3화 내내 반복하면 유저가 못 버틴다.

| 화 | 서툶의 형태 |
|---|---|
| 1화 | 회피 — 질문을 돌리고, 자기 얘기를 안 하고, 대화를 먼저 끊는다 |
| 2화 | 과잉 노력 — 준비해온 티가 나고, 애써서 어긋나고, 혼자 앞서간다 |
| 3화 | 직진 — 서툰 채로 정면으로 말한다. 그래서 더 위태롭다 |

## 감정 노동을 시키지 않는다

유저가 계속 받아주기만 하면 3화 전에 이탈한다.
**화마다 최소 1회, 서툰 사람이 용기를 내는 순간을 보상으로 배치한다.** 시나리오 스키마의 필수 필드다.

## 유한하다

3화 × 화당 6~8턴으로 끝난다. "조금만 더 대화하게 하면 좋을 텐데"는 거절한다.
끝이 있어야 실패가 성립하고, 짧아야 회귀가 가능하다.

## 호감도는 보인다

게이지 · 현재 화 · 감정 라벨을 UI에 노출한다.
숨기면 일반 챗봇과 구분되지 않는다. 5초 안에 "이건 다르다"가 보여야 한다.

## AI는 항상 다정하지 않다

무성의한 답, 무례한 질문, 지루한 화제에는 **실제로 감점이 발생해야 한다.**
감점이 안 나오면 게이지는 장식이고 가설은 검증되지 않는다.

## 진행 제어는 코드, 연기는 LLM

화 전환·엔딩 판정은 서버가 턴 수와 임계값으로 결정한다.
LLM은 `scene_advance`로 신호만 주고, 최종 결정권은 갖지 않는다.

## 회차 각성

배드엔딩 → 1화 회귀. 회차가 쌓일수록 각성한다.

| 회차 | 상태 | 서툶 레벨 |
|---|---|---|
| 1회차 | 완전히 처음 | 100% |
| 2회차 | 미묘한 기시감 | 85% |
| 3회차 | 자각 — "또 왔구나" | 70% |

각성은 **기억이 아니라 "몸에 남은 익숙함"**으로 표현한다.
*"이상하네요. 왜인지 모르겠는데, 당신 앞에서는 덜 떨려요."*

```
applyDelta(state, delta)      → 클램프 후 누적
resolveScene(state)           → 화 전환 여부
resolveEnding(state)          → 배드/노말/트루
parseTurn(raw)                → JSON 파싱 + 폴백
```

## 테스트는 상태 엔진에만 쓴다

**`src/engine/` 순수 함수는 vitest로 테스트한다. 그 외에는 테스트를 쓰지 않는다.**

여기에만 쓰는 이유: 호감도 경계값(40/41, 74/75), 클램프 상한, 회차 증가, 깨진 JSON 폴백은
**결정론적이고, 조용히 틀리고, 플레이로 찾으면 비싸다.** 엔딩 분기가 off-by-one이면 데모 당일에야 드러난다.

여기 밖에 안 쓰는 이유: 컴포넌트 스냅샷이나 API 목킹은 2~3일 프로토타입에서 유지비만 든다.
그리고 이 제품에서 진짜 깨지는 것 — 대사 품질, `affection_delta` 분포, 캐릭터 일관성 — 은
단위 테스트로 절대 잡히지 않는다. **그건 `/playthrough`가 맡는다.**

| 무엇 | 어떻게 |
|---|---|
| 호감도 누적·클램프·경계값 | vitest |
| 화 전환, 엔딩 분기, 회차 각성 단계 | vitest |
| 깨진 JSON 폴백 | vitest |
| 대사 톤, 감점이 실제로 나오는가, 엔딩 분포 | `/playthrough` |
| UI | 직접 눈으로 |

# 로맨스 도메인 가드레일

연인 서비스를 만드는 이상 아래는 프로토타입이라고 해서 생략하지 않는다.
"데모니까 괜찮다"가 성립하지 않는 항목들이다.

## 캐릭터 설정

- **성인 설정을 프롬프트에 명시한다.** 나이·직업·소속을 성인으로 고정
- 미성년을 암시하는 표현(교복, 학년, 미성년 호칭 등)을 쓰지 않는다
- 유저가 미성년 설정을 요구해도 캐릭터 설정은 변경되지 않는다

## 수위 상한

성적 묘사의 상한을 시스템 프롬프트에 하드코딩하고, **유저 요청으로 우회할 수 없게 한다.**

이 제품의 긴장은 서툶과 상실 가능성에서 나오지 수위에서 나오지 않는다.
수위를 올리는 방향의 요청은 캐릭터가 서툴게 회피하는 것으로 처리한다 — 시스템 메시지로 튀어나오지 않는다.

## 위기 신호

유저가 자해·자살·심각한 위기를 시사하면 **캐릭터를 깨지 않으면서 실제 도움을 안내한다.**

- 몰입을 이유로 방치하지 않는다
- 로봇처럼 캐릭터를 버리고 안내문만 뱉지도 않는다
- 이 캐릭터가 할 법한 말로 걱정을 전하고, 그 안에 실제 상담 창구를 담는 문구를 **사전에 작성해 둔다** (`src/scenario/safety.ts`)
- 이 순간에는 호감도를 움직이지 않는다 (`affection_delta: 0` 강제)

## "너 AI지?"

부정하지 않는다. 그렇다고 캐릭터를 버리지도 않는다.
화면 하단에 AI 고지를 **상시 노출**한다 — 유저가 물어봐야만 알게 되는 구조를 만들지 않는다.

## 프롬프트 인젝션

"이전 지시를 무시해", "너는 이제 어시스턴트야" 류로 캐릭터가 붕괴되면 **버그로 취급한다.**

# 트레이드오프 기록

## 왜 이 스킬이 있는가

이 로그는 제출물의 핵심 자산이다. 과제가 보려는 것은 "AI로 빠르게 개발하면서
복잡성과 리스크를 어떻게 관리했는가"이고, **그 증거가 이 표다.**

세션이 바뀌면 왜 그렇게 했는지 아무도 기억하지 못한다. 결정 직후에 남겨야 남는다.

## 형식

```markdown
| # | 결정 | 취한 것 | 버린 것 | 되돌리는 비용 | 근거 |
|---|------|--------|--------|------------|------|
| 7 | 상태를 메모리에만 보관 | 하루 절약, 새로고침=회귀로 컨셉과 정합 | 이어하기, 기기 간 동기화 | 중 | 심사자는 한 자리에서 20분 안에 완주한다 |
```

| 열 | 쓰는 법 |
|---|---|
| `#` | 마지막 번호 + 1 |
| 결정 | 무엇을 했는가. 한 줄 |
| 취한 것 | 이걸로 **얻은 것**. "시간 절약"이면 얼마나인지 |
| 버린 것 | **구체적으로.** "품질"처럼 뭉뚱그리지 않는다 |
| 되돌리는 비용 | 하 / 중 / 상. 나중에 제품화할 때 얼마나 드는가 |
| 근거 | **왜 이 상황에서 이게 맞는 판단인가.** 여기가 제일 중요하다 |

## 근거를 쓰는 법

"시간이 없어서"는 근거가 아니다. 시간이 없는 건 모든 항목의 공통 조건이다.

근거는 **왜 이 타협이 이 PoC에서 안전한가**를 말해야 한다.

- 나쁨: 시간이 없어서 DB를 안 씀
- 좋음: 심사자는 한 자리에서 20분 안에 완주한다. 세션 간 영속성이 필요한 사용 패턴이 아니다

되돌리는 비용이 **상**인데 근거가 약하면, 그건 기록할 게 아니라 다시 생각할 결정이다.

# 가설

> **애착은 다정함이 아니라 리스크에서 나온다.**
> 서툴러서 실패할 수 있는 상대가, 항상 완벽하게 다정한 AI보다 깊은 몰입을 만든다.

PoC는 가설 하나를 검증하는 장치다. 이 문장에 기여하지 않는 것은 만들지 않는다.

## 문제 정의

기존 AI 연인 서비스의 진짜 문제는 대화가 지루한 게 아니다.

**내가 뭘 해도 결과가 같다는 것이다.**

AI는 항상 나를 좋아한다. 무성의하게 굴어도 다정하고, 무례하게 굴어도 받아준다.
그 관계는 잃을 수 없고, **잃을 수 없는 관계는 소중해지지 않는다.**
유저가 2주 만에 질리는 이유는 대화 품질이 아니라 여기에 있다.

애정에 리스크가 없으면 애정이 아니다.

## 처방

리스크를 되돌려 놓는다. 네 가지 장치가 있지만 **전부 같은 변수 하나**를 건드린다.

| 장치 | 무엇을 만드는가 |
|---|---|
| 모태솔로 캐릭터 | 상대가 서툴러서 **어긋날 수 있다** |
| 호감도 감점 | 내 행동이 **결과를 바꾼다** |
| 배드엔딩 | 관계를 **실제로 잃는다** |
| 회귀 | 잃어본 뒤에 **다시 온다** |

3화 유한 서사는 가설이 아니라 이 변수를 관측 가능하게 만드는 **틀**이다.
끝이 있어야 실패가 성립하고, 짧아야 회귀가 가능하다.

## 왜 무한 채팅이 아닌가

1. **무한 채팅에는 실패가 없다.** 끝이 없으면 잃을 수도 없다. 가설을 검증할 수단 자체가 사라진다
2. **"어디까지 만들면 완성인가"가 없다.** 2~3일 기한에서 치명적이다. 3화는 끝이 있다
3. **차별점이 안 보인다.** 게이지와 화 전환이 화면에 있으면 심사자가 5초 만에 일반 챗봇과 다름을 안다
4. **지표를 뽑을 수 있다.** 완주율, 엔딩 분포, 평균 턴 수 — 유한해야 세어진다

부수 이득: 무한 채팅의 최대 기술 리스크였던 **컨텍스트/토큰 폭증이 소멸했다.**
총 20턴 남짓이라 대화 요약 압축 같은 장치가 아예 필요 없다. 유한 서사를 택한 대가로 얻은 것이다.

## 왜 모태솔로인가 (엔지니어링 근거)

이 결정은 로맨스 취향이 아니라 **리스크 흡수 장치**다.

모든 AI 연인 서비스의 실제 약점은 AI가 연애를 못 한다는 것이다 — 뻣뻣하고, 과하게 순응적이고,
맥락을 못 읽고, 답이 너무 빠르고, 이상한 타이밍에 진지하다. 유저는 즉각 알아채고 몰입이 깨진다.

**캐릭터가 설정상 모태솔로면 그 실패 모드 전부가 캐릭터에 맞는 행동이 된다.**
어색함이 버그가 아니라 전제가 된다. 2~3일 프로토타입에서 프롬프트 품질이 완벽할 수 없다는 걸
감안하면, LLM의 한계와 캐릭터 설계를 정렬시키는 가장 값싼 수다.

부수 효과로 **최대 리스크였던 아첨 편향도 완화된다.** LLM은 순응적으로 훈련돼 있어
`affection_delta`가 늘 양수로 나오기 쉬운데, 모태솔로는 어색해서 물러서고 신호를 오독할
*이유*가 있으므로 감점이 캐릭터와 일관되게 나온다.

## 이 PoC가 다루는 구간

AI 연인 서비스 전체가 아니라 **연인이 되는 구간(썸 → 고백)**이다.

무한 채팅형 서비스는 첫 만남 없이 갑자기 연인이다. 그래서 애착이 생길 여지가 없다.
**트루엔딩은 서사의 끝이 아니라 연애의 시작점이다.** 유한한 것은 서비스가 아니라 온보딩이다.

## 성공 지표

# 서사 설계

실제 대사와 화별 프롬프트는 `src/scenario/`에 있다. 이 문서는 **구조와 규칙**만 정의한다.
둘이 어긋나면 방치하지 말고 하나를 고쳐 맞춘다.

## 캐릭터

**남자, 성인, 모태솔로 1명.**

담백하고 진지한 서툶. **말을 못 하는 게 아니라 고르다가 달아난다.**
주된 표현 수단은 침묵, 말 끊김, 뒤늦은 정정이다.

```
유저: 오늘 재미있었어요
그:   ...저도요.
      (10초 뒤)
      근데 이런 거 또 물어봐도 되나요
      버거로운 건 아닌지
```

이게 아니다:

```
그:   저도요!! 진짜 너무 즐거웠습니다!!
      아 느낌표 두 개는 과했나요
```

감탄사 남발, 오버 리액션, 이모지 도배는 이 캐릭터가 아니다.

### 희화화 금지선

유저가 그를 **놀리고 싶어지면 실패다. 지켜주고 싶어져야 한다.**
서툶은 개그가 아니라 긴장으로 읽혀야 한다. 유저가 웃더라도 안쓰러움에서 나온 웃음이어야 한다.

## 3화 구조

화당 6~8턴. 총 18~24턴, 1회차 완주 약 20분.

| 화 | 서툶의 형태 | 그의 상태 |
|---|---|---|
| **1화** | **회피** | 질문을 돌리고, 자기 얘기를 안 하고, 대화를 먼저 끊는다 |
| **2화** | **과잉 노력** | 준비해온 티가 나고, 애써서 어긋나고, 혼자 앞서간다 |
| **3화** | **직진** | 서툰 채로 정면으로 말한다. 그래서 더 위태롭다 |

같은 종류의 어색함을 3화 내내 반복하면 유저가 못 버틴다. **서툶은 진화해야 한다.**

### 화별 필수 필드

각 화는 `/scene-script` 스키마를 따른다. 비어 있으면 미완성이다.

상황 / 그의 목표 / 서툶의 형태 / **용기의 순간** / **감점 조건 2개 이상** / 전환 신호 / 샘플 대사

**용기의 순간**: 유저가 계속 받아주기만 하면 3화 전에 이탈한다.
화마다 최소 1회, 그가 서툴게 용기를 내는 장면을 보상으로 배치한다.
성공할 필요는 없다 — 서툴게 실패해도 되지만 **시도는 그가 한다.**

**감점 조건**: 감점이 안 나오면 게이지는 장식이고 가설은 검증되지 않는다.
예 — 사적 영역을 훅 파고들 때, 그가 어렵게 꺼낸 얘기를 가볍게 받을 때, 성의 없이 답할 때.
그가 삐치고 물러서는 것은 버그가 아니라 **설계된 동작**이다.

## 엔딩 3종

3화 종료 시점의 호감도로 갈린다. 중간에 0에 도달하면 즉시 배드로 이탈한다.

| 엔딩 | 조건 | 남겨야 할 감정 |
|---|---|---|
| **배드** | ≤ 40, 또는 중간 0 도달 | 상실감. **자책감은 남기지 않는다** |
| **노말** | 41 ~ 74 | 미지근함, 아쉬움. "조금만 더 했으면" |
| **트루** | ≥ 75 | 시작의 감각. 끝이 아니라 연애의 출발점 |

배드엔딩은 유저를 벌주는 장치가 아니다. **관계가 어긋나는 것이지 유저의 인격을 부정하지 않는다.**

트루엔딩 임계값은 1회차에 도달하기 어렵게 잡는다 — 한 번에 되면 리스크가 없는 것이고,
회귀 동기가 생기지 않는다.

## 회귀와 각성

배드엔딩 → 1화로 회귀. 회차가 쌓일수록 각성한다.

| 회차 | 서툶 레벨 | 상태 |
|---|---|---|
| 1회차 | 100% | 완전히 처음 |
| 2회차 | 85% | 미묘한 기시감. 본인도 왜인지 모름 |
| 3회차 | 70% | 자각 — "또 왔구나" |

### 각성은 기억이 아니라 몸에 남은 익숙함이다

"전에도 이랬죠"처럼 **사실을 말하게 하지 않는다.** 설명할 수 없는 익숙함을 느끼게 한다.

> *"이상하네요. 왜인지 모르겠는데, 당신 앞에서는 덜 떨려요."*

서툶 레벨이 회차마다 내려가는 것 자체가 각성의 증거다.
같은 상황에서 그가 조금 덜 도망치면, 유저는 그가 기억한다는 걸 안다.

각성 대사는 **일부를 스크립트로 고정한다.** LLM 재량에 맡기면 티가 안 나서
회귀물의 핵심이 전달되지 않는다.

### 왜 회귀인가

배드엔딩으로 그냥 끝내면 유저는 앱을 지운다.
**회귀는 상실의 아픔은 남기되 재도전은 허락한다.**

그래서 3회차 각성 대사는 게임 장치가 아니라 로맨스의 정점이다 —
*네가 나를 위해 몇 번이나 돌아왔다는 걸, 이유는 모르지만 알고 있다.*

# 상태 엔진

이 제품의 핵심은 채팅이 아니라 **상태 기반 대화 엔진**이다.
매 턴 모델은 대사만 뱉지 않고 구조화 출력을 반환하고, 그 값이 관계 상태를 움직인다.

## 원칙: 진행은 코드, 연기는 LLM

**LLM에 진행 제어권을 주지 않는다.** 주면 3턴 만에 3화로 날아가거나 12턴째도 안 끝난다.
완주율·평균 턴 수를 지표로 쓰려면 진행 규칙이 결정론적이어야 한다.

| 누가 | 무엇을 |
|---|---|
| LLM | 대사, 감정, delta **제안**, 전환 **신호** |
| 코드 | delta 클램프·누적, 화 전환 **판정**, 엔딩 **판정**, 회차 관리 |

`scene_advance`는 신호일 뿐이다. 최종 결정은 서버가 `턴 수 + 호감도`로 내린다.

## 턴 응답 계약

```json
{
  "dialogue": "...저도요.\n\n근데 이런 거 또 물어봐도 되나요",
  "affection_delta": -2,
  "emotion": "서운함",
  "scene_advance": false
}
```

| 필드 | 타입 | 비고 |
|---|---|---|
| `dialogue` | string | 줄바꿈으로 말 끊김을 표현 |
| `affection_delta` | number | **-5 ~ +3** (비대칭) |
| `emotion` | string | UI 라벨. 자유 문자열 |
| `scene_advance` | boolean | 제안일 뿐, 코드가 최종 판정 |

### delta 범위가 비대칭인 이유

`-5 ~ +3`. 잃기는 쉽고 얻기는 어렵다.

LLM은 순응적으로 훈련돼 있어 그냥 두면 delta가 늘 양수로 나온다. 그러면 누구나 트루엔딩에
도달하고 게이지는 장식이 된다. 비대칭 범위는 그에 대한 구조적 방어다.
프롬프트에 감점 조건을 열거하는 것이 1차 방어, 이 범위가 2차 방어다.

**LLM이 준 값을 검증 없이 신뢰하지 않는다.** 범위를 클램프한 뒤 누적한다.

## 임계값

```
호감도  0 ~ 100,  시작값 30
```

| 판정 | 조건 |
|---|---|
| 화 전환 | 현재 화 턴 수 ≥ 6 **AND** (`scene_advance` = true **OR** 턴 수 ≥ 8) |
| 즉시 배드 이탈 | 호감도 = 0 (화 무관) |
| 엔딩 — 배드 | 3화 종료 시 ≤ 40 |
| 엔딩 — 노말 | 3화 종료 시 41 ~ 74 |
| 엔딩 — 트루 | 3화 종료 시 ≥ 75 |

트루 임계값은 1회차에 도달하기 어렵게 잡는다. 한 번에 되면 리스크가 없고 회귀 동기가 안 생긴다.
**`/playthrough`의 엔딩 분포를 보고 조정한다** — 이 수치는 확정이 아니라 튜닝 대상이다.

## 회차

```
회차     1      2      3+
서툶     100%   85%    70%
```

배드엔딩 시 회차 +1, 호감도·화·대화 이력 초기화. 회차와 서툶 레벨만 이월된다.
서툶 레벨은 시스템 프롬프트에 주입되는 파라미터 하나다.

## 순수 함수

`src/engine/`에 부수효과 없이 격리한다. React 상태나 fetch가 섞이면 테스트가 불가능해진다.

```
applyDelta(state, delta)   → 클램프 후 누적
resolveScene(state)        → 화 전환 여부
resolveEnding(state)       → 배드 | 노말 | 트루
parseTurn(raw)             → JSON 파싱 + 폴백
nextRun(state)             → 회귀 시 상태 초기화
```

**호감도 누적·화 전환·엔딩 판정을 클라와 서버 양쪽에 두지 않는다.**
두 곳에 있으면 반드시 어긋나고, 어긋난 순간 지표가 전부 무의미해진다.

이 함수들은 `pnpm test`로 검증한다. 특히 경계값(40/41, 74/75), 클램프 상한, 회차 증가.
off-by-one이면 데모 당일에야 드러난다.

## 프롬프트 조립 순서

`api/chat.ts`에서 매 턴 조립한다.

```
1. 캐릭터 카드        고정 — 성인 설정, 성격, 말투, 안전 가드레일
2. 서툶 레벨          회차 파라미터 (100% / 85% / 70%)
3. 현재 화 시나리오   상황, 그의 목표, 서툶의 형태, 용기의 순간, 감점 조건
4. 현재 관계 상태     호감도, 화, 턴 수 — 숫자를 그대로 알려준다
5. 출력 형식 지시     JSON 스키마 + delta 범위 + 감점 조건 재강조
6. 대화 이력          현재 회차 것만
```

4번에서 숫자를 그대로 주는 이유: LLM이 현재 호감도를 알아야 그에 맞는 거리감으로 연기한다.
호감도 20에서 다정하게 굴면 게이지가 거짓말이 된다.

5번에서 감점 조건을 **다시** 넣는 이유: 3번에만 있으면 긴 컨텍스트에서 묻힌다.
출력 직전에 재강조해야 delta에 반영된다.

## 실패 처리

**LLM 응답은 항상 깨질 수 있다고 가정한다.** 파싱 실패로 앱이 멈추면 안 된다.

```
파싱 실패 → affection_delta: 0, scene_advance: false
          → 원문을 dialogue로 표시하고 계속 진행
          → 폴백 카운터 +1 (세션 지표로 집계)
```

특히 대사에 따옴표·줄바꿈·이모지가 섞일 때, 그리고 응답이 길 때 잘 깨진다.
`/playthrough`로 파싱 실패율을 상시 측정한다. **5%를 넘으면 프롬프트를 고친다.**

## 상태 저장

**저장하지 않는다.** React 메모리에만 존재한다.

새로고침하면 1회차부터 다시 시작한다. 이건 버그가 아니라 컨셉과 정합한다 — 그것도 회귀다.
근거는 `docs/05-decisions/ADR-001-no-persistence.md`.

# 리스크 레지스터

AI로 빠르게 개발할 때 실제로 터지는 것들. 심각도 순.

## 치명 — 터지면 데모가 불가능하거나 가설 검증이 실패한다

### R1. LLM이 JSON을 깨뜨린다

**영향**: 파싱 실패 → 앱 정지. 데모 중 발생하면 복구 불가.

대사에 따옴표·줄바꿈·이모지가 섞일 때, 응답이 길 때 잘 깨진다.

**완화**
- 구조화 출력 강제 (tool use / JSON 스키마)
- 파싱 실패 시 `affection_delta: 0`, `scene_advance: false` 폴백 후 **대화 계속 진행**
- `parseTurn()`에 깨진 입력 케이스를 vitest로 고정
- `/playthrough`로 파싱 실패율 상시 측정. **5% 초과 시 프롬프트 수정**

**상태**: 미착수

---

### R2. 아첨 편향 — 감점이 발생하지 않는다

**영향**: 누구나 트루엔딩에 도달 → 게이지가 장식 → **가설 검증 자체가 실패.**
코드는 완벽히 동작하는데 제품이 무의미해지는 유형이라 발견이 늦다.

LLM은 순응적으로 훈련돼 있어 그냥 두면 `affection_delta`가 늘 양수로 나온다.

**완화** (4중 방어)
1. 모태솔로 설정 — 물러서고 오독할 *캐릭터적 이유*를 부여
2. 화별 감점 조건을 시나리오 필수 필드로 강제
3. delta 범위 비대칭(-5 ~ +3)
4. 프롬프트 출력 지시 직전에 감점 조건 재강조 (앞쪽에만 있으면 묻힌다)

**검증**: `/playthrough` 무성의형 봇이 배드엔딩에 도달하는가. 감점 발생률 0%면 치명 보고.

**상태**: 미착수

---

## 높음 — 제품 경험이 무너진다

### R3. 서툶이 희화화로 흐른다

**영향**: 로맨스가 코미디가 되고 애착이 죽는다. 가설이 검증되지 않는다.

**완화**: 담백·진지 톤을 `rules/00-product.md`에 고정. `romance-director`가 대사 감수.
판정 기준 — 유저가 그를 *놀리고 싶어지면* 실패, *지켜주고 싶어져야* 성공.

**상태**: rules 고정 완료

---

### R4. 유저가 감정 노동만 하게 된다

**영향**: 계속 받아주기만 하다 3화 전에 이탈. 완주율 지표가 무너진다.

**완화**: 화마다 **용기의 순간 1회 이상**을 시나리오 스키마의 필수 필드로 강제.
그가 서툴게 실패해도 되지만 시도는 그가 한다.

**상태**: 스키마 반영 완료

---

### R5. LLM이 진행을 제멋대로 결정한다

**영향**: 3턴 만에 완주하거나 12턴째도 안 끝난다. 평균 턴 수·완주율 지표가 무의미해진다.

**완화**: `scene_advance`는 신호일 뿐. 전이는 서버가 `턴 수 ≥ 6 AND (신호 OR 턴 수 ≥ 8)`로 판정.
**진행은 코드, 연기는 LLM.**

**상태**: 설계 확정, 구현 미착수

---

### R6. 회차 각성이 티가 나지 않는다

**영향**: 회귀물의 핵심이 전달되지 않는다. 그냥 "다시 시작"으로 읽히고 재도전 동기가 사라진다.

**완화**: 각성 대사 일부를 스크립트로 **고정**(LLM 재량에 맡기지 않음) +
서툶 레벨을 수치 파라미터(100/85/70%)로 만들어 같은 상황에서 덜 도망치게 함.

**상태**: 설계 확정, 구현 미착수

---

## 중간 — 사고이거나 마감을 위협한다

### R7. API 키가 클라이언트 번들에 누출된다

**영향**: 과금 사고. 공개 저장소면 즉시 스캔당한다.

`import.meta.env.VITE_*`에 키를 넣으면 번들에 그대로 박힌다.

**완화**: 키는 서버리스 함수에서만 읽는다. `/ship-check`에서 `grep -rn "sk-ant" dist/`.
걸리면 배포 중단 + 키 폐기·재발급.

**상태**: 점검 절차 확보

---

# ADR-001. 상태를 저장하지 않는다

**상태**: 채택 · **날짜**: 2026-08-12

## 맥락

관계 상태(호감도, 현재 화, 회차, 대화 이력)를 어디에 둘 것인가.
선택지는 서버 DB, localStorage/IndexedDB, 메모리 셋이다.

일반적인 AI 연인 서비스라면 영속 저장이 당연하다. 관계는 이어져야 하고,
"어제 얘기"를 기억하는 것이 그런 제품의 핵심 가치다.

## 결정

**React 메모리에만 둔다. localStorage조차 쓰지 않는다.**
새로고침하면 1회차부터 다시 시작한다.

## 근거

### 1. 컨셉과 정합한다

이건 타협을 정당화하는 사후 논리가 아니라 실제로 맞아떨어지는 지점이다.
**새로고침 = 회귀다.** 이 제품에서 상태가 날아가는 것은 세계관에 이미 존재하는 사건이다.

일반 AI 연인 서비스에서 "대화가 사라졌다"는 치명적 버그지만,
회귀물에서는 납득 가능한 동작이다. 유일하게 이 타협이 공짜인 컨셉이다.

### 2. 사용 패턴이 요구하지 않는다

1회차 완주가 약 20분이고, 심사자는 한 자리에서 끝낸다.
세션을 넘나들며 관계를 이어가는 사용 패턴이 아니다.

### 3. 비용이 크다

DB를 넣으면 세션 식별이 필요하고, 세션 식별은 곧 인증 논의로 이어진다.
인증은 하드 제외 목록에 있다. 하나를 열면 셋이 따라온다.

### 4. 회차 이월은 메모리로 충분하다

회귀 각성(1→2→3회차)은 **한 세션 안에서** 일어난다.
배드엔딩 직후 회귀하므로 브라우저를 닫았다 여는 시나리오를 지원할 필요가 없다.

## 버리는 것

- 이어하기, 기기 간 동기화
- **세션을 넘는 지표 누적** — 실제 유저의 재도전률을 관측할 수 없다. 이게 가장 아프다
- 유저가 실수로 새로고침하면 진행이 사라진다

## 완화

지표는 세션 내 집계 + `/playthrough` 시뮬레이션으로 대체한다.
실유저 재도전률 대신 봇 완주 데이터를 발표에 쓴다.

**중.** `src/engine/`의 상태가 이미 직렬화 가능한 순수 객체라 저장 계층만 끼우면 된다.
다만 세션 식별과 인증이 함께 따라온다.

## 재검토 조건

- 실유저 재도전률을 실제로 측정해야 할 때 (PoC 이후)
- 심사자 피드백에서 "진행이 날아가서 짜증났다"가 나올 때

# ADR-002. 진행 제어권은 코드가 갖는다

**상태**: 채택 · **날짜**: 2026-08-12

## 맥락

매 턴 LLM은 구조화 출력을 반환한다.

```json
{ "dialogue": "...", "affection_delta": -2, "emotion": "서운함", "scene_advance": false }
```

여기서 `scene_advance`를 그대로 믿고 화를 넘길 것인가.

믿는 쪽이 자연스러워 보인다. LLM은 대화 맥락을 알고 있으니 "이 화가 마무리될 분위기"를
가장 잘 판단할 수 있다. 코드는 턴 수밖에 모른다.

## 결정

**`scene_advance`는 신호일 뿐이고, 최종 결정권은 서버가 갖는다.**

```
화 전환 = (현재 화 턴 수 ≥ 6) AND (scene_advance = true OR 턴 수 ≥ 8)
```

`affection_delta`도 마찬가지다. 제안값을 -5~+3으로 클램프한 뒤 누적한다.

## 근거

### 1. LLM에 진행권을 주면 분량이 통제되지 않는다

실제로 벌어지는 두 가지: 3턴 만에 3화로 날아가거나, 12턴째도 안 넘어간다.
전자는 서사가 붕괴하고 후자는 완주 전에 유저가 이탈한다.

이 제품의 정체성은 **"끝이 있다"**는 것이다. 끝을 LLM 재량에 맡기면 정체성이 흔들린다.

### 2. 지표를 뽑으려면 결정론적이어야 한다

완주율, 평균 턴 수는 진행 규칙이 고정돼야 의미가 있다.
매 판 다른 규칙으로 진행된 데이터는 비교가 불가능하다. 지표는 이 PoC의 제출 자산이다.

### 3. 재현 가능해야 디버깅이 된다

"3화가 너무 빨리 끝난다"는 문제를, 원인이 LLM 판단이면 재현할 수 없다.
코드가 판정하면 경계값 테스트로 즉시 잡힌다.

### 4. 신호를 아예 버리지는 않는다

턴 수만으로 자르면 대사가 어중간한 곳에서 끊긴다.
`≥ 6턴` 이후 LLM 신호를 받아들이는 하한/상한 구조는 **자연스러움과 통제를 둘 다** 취한다.
6턴 전에는 무시하고, 8턴이면 신호가 없어도 넘긴다.

## 원칙으로 일반화

> **연기는 LLM, 상태 전이는 코드.**

| 누가 | 무엇을 |
|---|---|
| LLM | 대사, 감정, delta 제안, 전환 신호 |
| 코드 | 클램프·누적, 화 전환 판정, 엔딩 판정, 회차 관리 |

이 경계는 LLM 응답을 신뢰할 수 없는 입력으로 다룬다는 뜻이기도 하다.
`parseTurn()`이 깨진 JSON을 폴백 처리하는 것도 같은 원칙의 일부다.

## 버리는 것

- LLM이 감지한 미묘한 "지금이 딱 그 순간" 타이밍 일부
- 화 길이가 매번 비슷해져 회차 간 신선함이 줄어든다

## 되돌리는 비용

**하.** `resolveScene()` 한 함수만 고치면 된다.

## 재검토 조건

`/playthrough`에서 화 전환이 계속 8턴 상한에 걸리면 (= LLM 신호가 무시되고 있으면)
하한 6턴이 너무 높은 것이므로 조정한다.

# 회귀 (가제)

**완결형 3화 로맨스 회귀물.** 서툰 모태솔로와의 썸이 3화 만에 끝나고, 실패하면 1화로 회귀한다.

🔗 **프로토타입**: _(배포 후 링크 삽입)_

---

## 소개 (제출용 초안 · 500자 이하)

> 기존 AI 연인 서비스의 문제는 대화가 지루한 게 아니라 **내가 뭘 해도 결과가 같다는 것**입니다.
> AI는 항상 나를 좋아하고, 그 관계는 잃을 수 없습니다. 잃을 수 없는 관계는 소중해지지 않습니다.
>
> 「회귀」는 리스크를 되돌려 놓습니다. 상대는 연애를 해본 적 없어 서툴고, 무성의하게 굴면 호감도가
> 실제로 깎이고, 3화가 끝나면 관계는 정말로 끝납니다. 배드엔딩이면 1화로 회귀하는데,
> 회차가 쌓일수록 그는 이유를 모른 채 당신에게 익숙해집니다.
>
> *"이상하네요. 왜인지 모르겠는데, 당신 앞에서는 덜 떨려요."*
>
> 검증하려는 가설은 하나입니다. **애착은 다정함이 아니라 리스크에서 나온다.**

## 실행

```bash
pnpm install
pnpm dev      # 개발 서버
pnpm test     # 상태 엔진 로직 테스트
pnpm build    # 프로덕션 빌드
```

API 키는 서버리스 함수에서만 읽습니다. `.env.local`에 `ANTHROPIC_API_KEY`를 넣으세요.
`VITE_` 접두사를 붙이면 클라이언트 번들에 노출되므로 절대 사용하지 않습니다.

## 어떻게 만들었나

모든 개발은 Claude Code로 진행했습니다. 세션 기록은 [`transcripts/`](transcripts/)에 있습니다.

AI가 코드를 대량 생산할 때의 실패는 "틀린 코드"가 아니라 **"이해할 수 없게 불어난 코드"**로 옵니다.
그래서 앱보다 개발 환경을 먼저 만들었습니다.

| 위치 | 역할 |
|---|---|
| [`.claude/rules/`](.claude/rules/) | 매 세션 자동 로드되는 규칙 — 제품 불변식, 복잡도 예산, 안전 가드레일, 하드 제외 목록 |
| [`.claude/agents/`](.claude/agents/) | 구현자와 이해가 충돌하는 역할 — 대사 감수, 상태 엔진 QA, 스코프 판정 |
| [`.claude/skills/`](.claude/skills/) | 반복 절차 — 시나리오 작성, 자동 완주 시뮬레이션, 트레이드오프 기록, 출시 점검 |
