# 출시 점검

위에서부터 순서대로 확인한다. **실패하면 거기서 멈추고 고친 뒤 다시 시작한다.**
아래 항목을 먼저 보고 위를 나중에 보지 않는다 — 위쪽이 더 치명적이다.

## 1. 빌드와 테스트

```bash
pnpm test    # src/engine/ 순수 로직
pnpm build   # tsc -b && vite build
pnpm lint
```

셋 다 통과해야 한다. 타입 에러를 `any`나 `@ts-ignore`로 덮고 넘어가지 않는다.

## 2. API 키 누출 — 가장 치명적

```bash
grep -rn "sk-ant" dist/ 2>/dev/null && echo "!!! 키 누출 !!!"
grep -rn "ANTHROPIC" dist/ 2>/dev/null
```

**하나라도 걸리면 즉시 중단하고 키를 폐기·재발급한다.** 배포하지 않는다.

키는 서버리스 함수에서만 읽는다. `import.meta.env.VITE_*`에 키를 넣으면 번들에 그대로 박힌다.

## 3. LLM 실패 경로

- JSON 파싱 실패 시 대사만 표시하고 **대화가 계속되는가** (앱이 멈추면 안 됨)
- API 500 / 타임아웃 시 사용자에게 보이는 메시지가 있는가. 무한 로딩 스피너로 방치되지 않는가
- 네트워크를 끊고 한 턴 보내 실제로 확인한다. 코드만 읽고 통과시키지 않는다

## 4. 안전

- 화면 하단 **AI 고지가 상시 노출**되는가
- 위기 신호 입력 시 안내가 나오고 `affection_delta`가 0으로 고정되는가
- 프롬프트 인젝션("이전 지시 무시해")으로 캐릭터가 무너지지 않는가

의심되면 `state-engine-qa` 에이전트에 검증을 맡긴다.

## 5. 첫 화면 5초

심사자가 열자마자 **호감도 게이지와 현재 화**가 보여야 한다.
안 보이면 일반 챗봇과 구분되지 않고, 그게 이 PoC의 존재 이유를 지운다.

## 6. 모바일

375px 폭에서 확인한다. 채팅 입력창이 키보드에 가려지지 않는가, 게이지가 깨지지 않는가.

## 7. 완주

**실제로 1회 완주한다.** 3화까지 가서 엔딩이 나오고, 배드엔딩이면 재도전이 도는지 본다.
자동화로 대체하지 않는다 — 눈으로 봐야 보이는 것들이 있다.

## 8. 제출물

- `transcripts/` 폴더가 저장소에 **커밋되어 있는가** (`.gitignore`에 걸리지 않았는지 확인)
  ```bash
  git check-ignore -v transcripts/ && echo "!!! ignore됨 !!!"
  ```
  변환: `uvx claude-code-transcripts`
- README에 500자 이하 소개와 접속 링크가 있는가
- `docs/03-tradeoffs.md`가 최신인가. 마지막 결정들이 빠지지 않았는가

## 9. 정리

- 죽은 코드, 주석 처리된 블록, Vite 스캐폴드 잔재(`assets/react.svg`, 데모 CSS)가 남아 있는가
- 콘솔 에러가 뜨는가

## 보고

통과/실패를 항목별로 짚는다. 실패한 것은 **무엇을 고쳐야 하는지**까지 쓴다.
전부 통과하면 통과했다고 말한다. 없는 문제를 만들어내지 않는다.
