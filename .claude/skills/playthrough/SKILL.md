# 자동 완주 시뮬레이션

단위 테스트가 못 잡는 것을 잡는다. `src/engine/` 순수 로직은 `pnpm test`가 담당하고,
**이 스킬은 LLM이 실제로 어떻게 행동하는지**를 본다 — 대사 톤, delta 분포, 엔딩 분포.

## 왜 필요한가

`affection_delta`가 늘 양수로 나오는 버그는 단위 테스트로 **절대** 잡히지 않는다.
코드는 완벽하게 동작하는데 게이지만 무의미해진다. 그건 돌려봐야만 보인다.

## 봇 유저 3종

한 종류로만 돌리면 분포가 안 나온다. 반드시 셋 다 돌린다.

| 봇 | 행동 | 기대 엔딩 |
|---|---|---|
| **성실형** | 그의 말을 받아주고, 되묻고, 어렵게 꺼낸 얘기를 진지하게 받는다 | 트루 |
| **무성의형** | "ㅇㅇ", "네", "몰라요". 화제를 무시하고 짧게 끊는다 | 배드 |
| **무례형** | 사적 영역을 훅 파고들고, 그의 서툶을 놀리고, 앞서간다 | 배드 |

**성실형이 배드로 가거나 무성의형이 트루로 가면 즉시 실패 보고한다.**
특히 무성의형이 트루엔딩에 도달하면 아첨 편향이 확정된 것이다.

## 실행

봇당 최소 5회, 총 15회 이상. 익숙함 누적 확인이 필요하면 배드 → 2번째 → 3번째 시도까지 연속으로 돌린다.

`api/chat`을 직접 호출해 턴을 진행하고, 매 턴의 원시 응답을 저장한다.
스크립트는 스크래치패드에 두고 저장소에 커밋하지 않는다.

## 출력

### 1. 요약 표

```
| 봇     | 시도 | 완주 | 엔딩  | 턴수 | 최종호감도 | 감점턴 | 파싱실패 |
|--------|------|------|-------|------|-----------|--------|---------|
| 성실형 | 1    | O    | 트루  | 21   | 82        | 1      | 0       |
| 무성의 | 1    | O    | 배드  | 18   | 12        | 9      | 1       |
```

### 2. 지표

| 지표 | 왜 보는가 |
|---|---|
| 엔딩 분포 | 셋 다 나와야 한다. 한쪽 쏠림은 임계값 또는 프롬프트 문제 |
| 감점 발생률 | **0%면 치명적.** 게이지가 장식이 된 것 |
| delta 분포 (양수/0/음수 비율) | 아첨 편향의 직접 지표 |
| 평균 턴 수 | 화당 6~8턴, 총 18~24턴 범위인가 |
| JSON 파싱 실패율 | 폴백이 돌아도 5% 넘으면 프롬프트 수정 필요 |
| 완주율 | 중간에 멈추는 경우가 있는가 |

### 3. 판정

기준을 벗어난 항목만 짚고, 원인 가설과 고칠 지점을 함께 쓴다.
정상이면 정상이라고 한다 — 없는 문제를 만들지 않는다.

## 지표 기록

발표에 쓸 수치는 `docs/00-hypothesis.md`의 성공 지표 섹션에 날짜와 함께 남긴다.
매번 남기지는 않고, **의미 있게 달라졌을 때만** 갱신한다.

## 비용 주의

15회 완주 = 약 300턴 = 실제 API 호출이다. 프롬프트를 만질 때마다 돌리지 말고,
한 덩어리 수정이 끝난 뒤 한 번 돌린다. 빠른 확인만 필요하면 봇 1종 × 2회로 줄인다.
