# 복잡도 예산

AI가 코드를 대량 생산할 때의 실패는 "틀린 코드"가 아니라 **"이해할 수 없게 불어난 코드"**로 온다.
막판에 디버깅이 불가능해지는 것이 이 프로젝트의 진짜 마감 리스크다. 아래는 그걸 막는 상한선이다.

## 상태 전이 로직은 한 곳에만

호감도 누적 · 화 전환 · 엔딩 판정을 클라이언트와 서버 양쪽에 두지 않는다.
두 곳에 있으면 반드시 어긋나고, 어긋난 순간 지표가 전부 무의미해진다.

LLM이 준 `affection_delta`를 **검증 없이 신뢰하지 않는다.** 범위를 클램프한 뒤 누적한다.

## 상태 엔진은 순수 함수로 격리한다

`src/engine/`에 부수효과 없는 함수로 분리한다. React 상태나 fetch가 섞이면 테스트가 불가능해진다.

```
applyDelta(state, delta)      → 클램프 후 누적
resolveScene(state)           → 화 전환 여부
resolveEnding(state)          → 배드/노말/트루
parseTurn(raw)                → JSON 파싱 + 폴백
```

## 테스트는 상태 엔진에만 쓴다

**`src/engine/` 순수 함수는 vitest로 테스트한다. 그 외에는 테스트를 쓰지 않는다.**

여기에만 쓰는 이유: 호감도 경계값(40/41, 74/75), 클램프 상한, 회차 증가, 깨진 JSON 폴백은
**결정론적이고, 조용히 틀리고, 플레이로 찾으면 비싸다.** 엔딩 분기가 off-by-one이면 데모 당일에야 드러난다.

여기 밖에 안 쓰는 이유: 컴포넌트 스냅샷이나 API 목킹은 2~3일 프로토타입에서 유지비만 든다.
그리고 이 제품에서 진짜 깨지는 것 — 대사 품질, `affection_delta` 분포, 캐릭터 일관성 — 은
단위 테스트로 절대 잡히지 않는다. **그건 `/playthrough`가 맡는다.**

| 무엇 | 어떻게 |
|---|---|
| 호감도 누적·클램프·경계값 | vitest |
| 화 전환, 엔딩 분기, 회차 각성 단계 | vitest |
| 깨진 JSON 폴백 | vitest |
| 대사 톤, 감점이 실제로 나오는가, 엔딩 분포 | `/playthrough` |
| UI | 직접 눈으로 |

로직을 고쳤으면 `pnpm test`가 통과한 뒤에 커밋한다.

## 수치 상한

| 항목 | 상한 |
|---|---|
| 파일당 줄 수 | 200 |
| `api/` 서버리스 함수 | 1개 |
| 컴포넌트당 props | 7개 |
| 런타임 의존성 추가 | `docs/03-tradeoffs.md`에 1줄 근거 필수 |

상한을 넘으면 **분리하기 전에 기능 축소를 먼저 검토한다.** 쪼개서 통과시키는 건 예산을 우회하는 것이다.

## 추상화는 3번째 중복부터

2번까지는 복붙을 유지한다. 2~3일짜리 프로토타입에서 조기 추상화는 언제나 손해다.

## 죽은 코드는 즉시 삭제

주석 처리해서 남기지 않는다. 필요하면 git에서 꺼낸다.
Vite 스캐폴드 잔재(`App.css` 데모 스타일, `assets/react.svg` 등)도 쓰지 않게 된 시점에 지운다.

## LLM 응답은 항상 깨질 수 있다고 가정한다

JSON 파싱 실패 시 앱이 멈추면 안 된다. `affection_delta: 0`, `scene_advance: false`로 폴백하고
대사만 표시한 뒤 계속 진행한다. 폴백 발생 횟수는 세션 지표로 집계한다.
