# 상태 엔진

이 제품의 핵심은 채팅이 아니라 **상태 기반 대화 엔진**이다.
매 턴 모델은 대사만 뱉지 않고 구조화 출력을 반환하고, 그 값이 관계 상태를 움직인다.

## 원칙: 진행은 코드, 연기는 LLM

**LLM에 진행 제어권을 주지 않는다.** 주면 3턴 만에 3화로 날아가거나 12턴째도 안 끝난다.
완주율·평균 턴 수를 지표로 쓰려면 진행 규칙이 결정론적이어야 한다.

| 누가 | 무엇을 |
|---|---|
| LLM | 대사, 감정, delta **제안**, 전환 **신호** |
| 코드 | delta 클램프·누적, 화 전환 **판정**, 엔딩 **판정**, 회차 관리 |

`scene_advance`는 신호일 뿐이다. 최종 결정은 서버가 `턴 수 + 호감도`로 내린다.

## 턴 응답 계약

```json
{
  "dialogue": "...저도요.\n\n근데 이런 거 또 물어봐도 되나요",
  "affection_delta": -2,
  "emotion": "서운함",
  "scene_advance": false
}
```

| 필드 | 타입 | 비고 |
|---|---|---|
| `dialogue` | string | 줄바꿈으로 말 끊김을 표현 |
| `affection_delta` | number | **-2 ~ +8** (비대칭 — 보상 우위) |
| `emotion` | string | UI 라벨. 자유 문자열 |
| `scene_advance` | boolean | 제안일 뿐, 코드가 최종 판정 |

### delta 범위가 비대칭인 이유

`-2 ~ +8`. **얻기가 잃기보다 크다 — 보상 우위다.**

> **2026-08-12 반전**: 초기 설계는 `-5 ~ +3`의 리스크 우위였다.
> 실플레이에서 "적극적으로 표현해도 +1"이라는 피로가 보고돼 배점을 뒤집었다.
> 리스크는 배점이 아니라 **배드엔딩·회귀·화별 상한**이 진다. 근거는 [#19](03-tradeoffs.md).

LLM은 순응적으로 훈련돼 있어 그냥 두면 delta가 늘 양수로 나온다. 그러면 누구나 트루엔딩에
도달하고 게이지는 장식이 된다.

**LLM이 준 값을 검증 없이 신뢰하지 않는다.** 범위를 클램프한 뒤 누적한다.

### 성의 상한 — 배점을 지키는 것은 프롬프트가 아니라 코드다

프롬프트에 "무성의는 0"이라고 써도 지켜지지 않는다. 실측(2026-08-12, Gemini):

| 유저 발화 | LLM이 준 delta |
|---|---|
| `"그래서요?"` | **+8** |
| `"괜찮았어요"` | **+8** |
| `"몰라요"` | **+4** |

그래서 유저 발화를 먼저 분류하고, 그 등급의 상한으로 LLM 제안값을 누른다.
**배점 자체는 건드리지 않는다 — 무엇이 보상받을 자격이 있는지만 코드가 정한다.**

| 등급 | 무엇인가 | 상한 |
|---|---|---|
| `none` | 내용이 없는 반응 토큰 (`ㅇㅇ`, `아 네 그렇군요`, `오 신기하다`) | **0** |
| `plain` | 성의는 있으나 먼저 다가오지는 않는 답 | **2** |
| `engaged` | 호감 표현·다음 만남 제안·그에게 되묻기·긴 자기 얘기 | **+8** (상한 없음) |

- **감점은 상한이 막지 않는다.** LLM이 무례로 판단해 준 음수는 그대로 통과한다.
- `engaged` 조건을 "문장 길이 > 12"로 두면 맞장구가 아닌 거의 모든 발화가 상한 8을 받아
  **화별 천장이 매 화 포화되고 무난형이 트루로 샌다**(실측 100). 되묻기·다가옴으로 좁혔다.
- `plain` 상한이 2인 이유: 최장 경로(강제 전환 5턴 × 3화 = 15턴)를 성의만으로 채워도
  `30 + 30 = 60`으로 트루 임계값 75에 닿지 않는다. 3이면 정확히 75가 되어 샌다.

## 임계값

```
호감도  0 ~ 100,  시작값 30
```

| 판정 | 조건 |
|---|---|
| 화 전환 | 현재 화 턴 수 ≥ 4 **AND** (`scene_advance` = true **OR** 턴 수 ≥ 5) |
| 즉시 배드 이탈 | 호감도 = 0 (화 무관) |
| 엔딩 — 배드 | 3화 종료 시 ≤ 40 |
| 엔딩 — 노말 | 3화 종료 시 41 ~ 74 |
| 엔딩 — 트루 | 3화 종료 시 ≥ 75 |

### 화별 호감도 천장

```
1화 ≤ 50    2화 ≤ 70    3화 ≤ 100
```

배점이 `+8`까지 열리면서 **1~2화에서 트루가 확정되는 문제**가 생겼다.
2화 천장(70)을 트루 임계값(75)보다 낮게 둬서 **트루는 3화에서만 열린다.**
이게 없으면 3화 구조가 판정상 무의미해진다.

트루 임계값은 **1회차에도 도달 가능하게** 잡는다. 회차를 강제로 태우는 것은 리스크가 아니라 지연이고,
실측에서 회차 보상은 최종 호감도를 사실상 움직이지 못했다(70.4 / 71.3 / 70.3).
리스크는 화별 천장·배드엔딩·유한함이 진다.
**`/playthrough`의 엔딩 분포를 보고 조정한다** — 이 수치는 확정이 아니라 튜닝 대상이다.

## 회차

```
회차     1      2      3+
서툶     100%   85%    70%
```

배드엔딩 시 회차 +1, 호감도·화·대화 이력 초기화. 회차와 서툶 레벨만 이월된다.
서툶 레벨은 시스템 프롬프트에 주입되는 파라미터 하나다.

**서툶 레벨은 대사 톤만이 아니라 delta에도 반영된다.** 2회차 이상에서는 같은 말에도
한 단계 후하게 준다고 프롬프트에 명시한다 — 이게 없으면 회귀해도 보상이 없어
회귀 동기 자체가 성립하지 않는다 (실측으로 확인됨).

## 순수 함수

`src/engine/`에 부수효과 없이 격리한다. React 상태나 fetch가 섞이면 테스트가 불가능해진다.

```
classifyEffort(text)       → none | plain | engaged
effortCeiling(text)        → 이 발화가 받을 수 있는 delta 상한
applyDelta(state, delta)   → 클램프 후 누적
resolveScene(state)        → 화 전환 여부
resolveEnding(state)       → 배드 | 노말 | 트루
parseTurn(raw)             → JSON 파싱 + 폴백
nextRun(state)             → 회귀 시 상태 초기화
```

**호감도 누적·화 전환·엔딩 판정을 클라와 서버 양쪽에 두지 않는다.**
두 곳에 있으면 반드시 어긋나고, 어긋난 순간 지표가 전부 무의미해진다.

이 함수들은 `pnpm test`로 검증한다. 특히 경계값(40/41, 74/75), 클램프 상한, 회차 증가.
off-by-one이면 데모 당일에야 드러난다.

## 프롬프트 조립 순서

`api/chat.ts`에서 매 턴 조립한다.

```
1. 캐릭터 카드        고정 — 성인 설정, 성격, 말투, 안전 가드레일
2. 서툶 레벨          회차 파라미터 (100% / 85% / 70%)
3. 현재 화 시나리오   상황, 그의 목표, 서툶의 형태, 용기의 순간, 감점 조건
4. 현재 관계 상태     호감도, 화, 턴 수 — 숫자를 그대로 알려준다
5. 출력 형식 지시     JSON 스키마 + delta 범위 + 감점 조건 재강조
6. 대화 이력          현재 회차 것만
```

4번에서 숫자를 그대로 주는 이유: LLM이 현재 호감도를 알아야 그에 맞는 거리감으로 연기한다.
호감도 20에서 다정하게 굴면 게이지가 거짓말이 된다.

5번에서 감점 조건을 **다시** 넣는 이유: 3번에만 있으면 긴 컨텍스트에서 묻힌다.
출력 직전에 재강조해야 delta에 반영된다.

## 실패 처리

**LLM 응답은 항상 깨질 수 있다고 가정한다.** 파싱 실패로 앱이 멈추면 안 된다.

```
파싱 실패 → affection_delta: 0, scene_advance: false
          → 원문을 dialogue로 표시하고 계속 진행
          → 폴백 카운터 +1 (세션 지표로 집계)
```

특히 대사에 따옴표·줄바꿈·이모지가 섞일 때, 그리고 응답이 길 때 잘 깨진다.
`/playthrough`로 파싱 실패율을 상시 측정한다. **5%를 넘으면 프롬프트를 고친다.**

## 상태 저장

**저장하지 않는다.** React 메모리에만 존재한다.

새로고침하면 1회차부터 다시 시작한다. 이건 버그가 아니라 컨셉과 정합한다 — 그것도 회귀다.
근거는 `docs/05-decisions/ADR-001-no-persistence.md`.

## 모델

`gemini-3.5-flash-lite` (무료 티어, `GEMINI_MODEL`로 교체 가능). `responseJsonSchema`로 턴 계약을 강제한다.

무료 티어 한도는 **모델별로 다른 버킷**이다 — `gemini-3.6-flash`는 20요청/**일**이라
완주 한 번(12턴)에 소진되고, `gemini-3.5-flash-lite`는 15요청/**분**이라 회복된다.
이 차이가 `/playthrough`를 돌릴 수 있는지를 가른다.
