# 트레이드오프 로그

무엇을 왜 포기했는지의 기록. **append-only** — 기존 행은 수정하지 않는다.

기록 규칙과 근거 쓰는 법은 `/tradeoff-log` 스킬 참조.
포기가 없었으면 트레이드오프가 아니다. 잘한 일을 자랑하는 로그가 아니다.

| # | 결정 | 취한 것 | 버린 것 | 되돌리는 비용 | 근거 |
|---|------|--------|--------|------------|------|
| 1 | 상태를 React 메모리에만 보관 (localStorage도 안 씀) | 하루 절약. 새로고침=회귀로 컨셉과 오히려 정합 | 이어하기, 기기 간 동기화, 세션 간 지표 누적 | 중 — DB + 세션 키 | 심사자는 한 자리에서 20분 안에 완주한다. 세션 간 영속성이 필요한 사용 패턴이 아니다. [ADR-001](05-decisions/ADR-001-no-persistence.md) |
| 2 | 테스트를 `src/engine/` 순수 로직에만 작성 | 경계값·클램프·폴백 버그를 싸게 차단 | 컴포넌트/API 계층 테스트 커버리지 | 하 — 나중에 추가 가능 | 조용히 틀리고 플레이로 찾으면 비싼 것만 테스트한다. 대사 품질과 delta 분포는 단위 테스트로 못 잡으므로 `/playthrough`가 맡는다 |
| 3 | Next.js 대신 현행 Vite SPA 유지 | 초기 셋업 0시간, 스캐폴드 그대로 사용 | 서버 상태, SSR, Route Handler 편의 | 상 — 재구성 | 서버가 필요한 유일한 이유가 API 키 보호이고 그건 서버리스 함수 1개로 족하다 |
| 4 | 캐릭터 1명 고정 | 프롬프트·대사 검수 대상이 1/N로 줄어 서사 품질에 집중 | 취향 선택, 캐릭터 간 비교 재미 | 하 — 시나리오 복제 | 가설은 "리스크가 애착을 만든다"이지 "선택지가 재미를 만든다"가 아니다. 캐릭터를 늘려도 가설 검증력은 그대로다 |
| 5 | 화별 분기 없음. 엔딩만 3갈래 | 프롬프트 경우의 수가 3화 × 1경로로 고정 | 선택에 따라 상황 자체가 바뀌는 풍부함 | 중 — 화별 프롬프트 분기 추가 | 2~3일에 분기를 넣으면 경우의 수가 급증해 모든 갈래의 대사 품질이 같이 나빠진다. 얕은 4갈래보다 깊은 1갈래가 가설을 더 잘 검증한다 |
| 6 | `affection_delta` 범위를 비대칭(-5 ~ +3)으로 고정 | 아첨 편향에 대한 구조적 방어 | 감정 변화의 세밀한 표현력 | 하 — 상수 하나 | LLM은 순응적으로 훈련돼 delta가 늘 양수로 나온다. 프롬프트 지시만으로는 못 막아서 범위로 강제한다 |
| 7 | 배포는 Vercel에 올리는 것까지만. 인프라 작업 안 함 | 접속 링크 확보에 30분 이하 | 커스텀 도메인, 모니터링, 리전 최적화, CI | 하 | 제출물에 필요한 건 "접속 가능한 링크"이지 운영 가능한 인프라가 아니다 |
| 8 | 의존성 추가: `vitest` (dev) | 상태 엔진 경계값 검증. `pnpm test` 스코프를 `src/engine`으로 제한 | 없음 (devDependency, 번들 미포함) | 하 | 규칙상 의존성 추가는 근거 기록 필수. 엔진 로직은 조용히 틀리고 플레이로 찾으면 비싸다 |
