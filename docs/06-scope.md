### M8 — 배포 (2026-08-13 완료)

`betterplaywon/ai-couple-poc`를 Vercel 대시보드에서 import했다. Framework Preset은 **Vite**로
자동 감지됐고 빌드 설정은 기본값 그대로 뒀다. **Environment Variables에 `ANTHROPIC_API_KEY`를 넣었다.**

**https://ai-couple-poc.vercel.app/**

프로덕션에서 처음 도는 경로를 실제로 확인했다 (2026-08-13, `curl`):

| 확인 항목 | 결과 |
|---|---|
| 앱이 뜨는가 | `GET /` → 200 `text/html` |
| `api/chat.ts`가 서버리스 함수로 잡혔는가 | `GET /api/chat` → 405, 빈 바디 POST → 400 — 핸들러가 도는 증거 |
| 유효한 턴이 실제 LLM을 타는가 | POST → 200, 2.8초, **`mock` 필드 없음** |
| `api/`가 `../src/`를 import하는 구조가 번들러에서 풀리는가 | 응답이 캐릭터 톤을 지킴 → `buildSystemPrompt`가 실행됐다 |
| ~~edge 런타임에서 `@anthropic-ai/sdk`가 도는가~~ | **불가 확인. Node 런타임으로 옮김** ([#28](03-tradeoffs.md)) |

응답 원문: `{"dialogue": "네.\n\n날씨 좋네요.", "affection_delta": 1, "emotion": "조용함", "scene_advance": false}`

> **`mock` 필드가 없다는 것이 키가 걸렸다는 증거다.** 키를 안 넣어도 배포는 성공하고 앱도 뜨지만
> 전 턴이 목업으로 돌아 대사가 스크립트가 된다 (`mock: "no_key"` + 화면 하단 `데모 모드` 문구).
> 재배포하거나 키를 교체한 뒤에는 이 POST를 다시 던져 `mock`이 없는지 확인한다.

로컬 dev 어댑터([#10](03-tradeoffs.md))로만 검증했던 경로가 프로덕션에서도 도는 것이 이로써 확인됐다.

### M11 — Claude 복귀 (2026-08-13 완료)

Gemini는 **크레딧 소진에 대한 임시 대응**이었다([#18](03-tradeoffs.md)).
`api/chat.ts`를 순수 프록시로 둔 덕에([#11](03-tradeoffs.md)) 교체는 예고대로 **한 파일**로 끝났다.

| 위치 | 전 | 후 |
|---|---|---|
| `api/chat.ts:1` | `@google/genai` | `@anthropic-ai/sdk` |
| `api/chat.ts:8` | `GEMINI_MODEL ?? 'gemini-3.5-flash-lite'` | `ANTHROPIC_MODEL ?? 'claude-haiku-4-5'` |
| `api/chat.ts:65` | `process.env.GEMINI_API_KEY` | `process.env.ANTHROPIC_API_KEY` |
| `api/chat.ts:79-91` | `generateContent` + `responseJsonSchema` | `messages.create` + `output_config.format` |
| `vite.config.ts` | — | `ANTHROPIC_` 이미 포함, 수정 없음 |

**바꾸지 않은 것:** `TURN_SCHEMA`(그대로 재사용), `buildSystemPrompt`, `src/engine/`, UI, 목업 폴백.

계획과 달랐던 것 둘:

- **`@anthropic-ai/sdk`는 의존성에 없었다.** [#18](03-tradeoffs.md)에서 Gemini로 갈 때 함께 제거됐고,
  이 문서의 "이미 의존성에 있음"은 [#9](03-tradeoffs.md) 시절 기준으로 남아 있던 낡은 기록이었다.
  `pnpm add @anthropic-ai/sdk`가 선행돼야 한다.
- **Anthropic은 첫 메시지가 `user`여야 한다.** 화의 고정 오프닝 때문에 이력이 assistant로 시작하므로
  앞쪽 assistant 턴을 떨어뜨리는 한 줄이 추가로 필요했다([#24](03-tradeoffs.md)).

복귀 후 반드시 `/playthrough`를 다시 돌린다. 성의 상한은 코드가 지므로 제공자가 바뀌어도
판별은 유지되지만, **`plain`/`engaged` 구간의 원시 delta 분포는 모델마다 다르다.**
무난형이 트루로 새거나 성실형이 노말에 그치면 프롬프트 루브릭을 재조정한다.

> 비용: 완주 1회 = 12~15턴. Haiku 4.5 기준 입력이 매 턴 시스템 프롬프트(~2.5K 토큰)를
> 새로 태우므로 완주당 대략 $0.05 안팎이다. 상태가 시스템 프롬프트에 박혀 있어
> 프롬프트 캐싱은 **지금 구조로는 효과가 없다** — 필요해지면 상태를 유저 메시지로 내려야 한다.

### M6 — 익숙함 누적 3연속 완주 (2026-08-13, Claude 실호출)

배드 → 2번째 → 3번째를 끊지 않고 이어서 완주시켰다. **폴백 0턴 · 파싱 실패 0턴** (전 턴 실호출).

| 시도 | 봇 | 서툶 | 엔딩 | 최종 호감도 | 턴 | 각성 고정 대사 |
|---|---|---|---|---|---|---|
| 1 | 무성의형 | 100% | 배드 | 24 | 14 | — (첫 시도엔 없음) |
| 2 | 무성의형 | 85% | 배드 | 26 | 15 | 1화 1턴 · **1회** |
| 3 | 성실형 | 70% | 트루 | 100 | 13 | 1화 1턴 · 3화 1턴 · **각 1회** |

- **고정 대사가 원문 그대로, 제 화·제 턴에, 딱 한 번씩 나온다.** 유저가 `"네"`만 던진 턴에서도 나왔다
  (이게 직전 실패 케이스였다 — 경위는 [#25](03-tradeoffs.md))
- **사실 진술 누수 0건.** `"전에도"`, `"지난번에"` 류가 시도를 건너 나온 적 없다
- 무성의형이 3화에서 `raw +8`을 두 번 받았고 `effortCeiling`이 둘 다 0으로 막았다 — 성의 상한 재확인

### `/playthrough` 재현 메모

하네스(`bots.mts`, `playthrough.mts`, `summarize.mjs`)는 **스크래치패드에 있고 커밋하지 않는다.**
세션이 바뀌면 사라지므로 `/playthrough`가 다시 만든다. 다시 만들 때 걸렸던 것:

- **봇과 게임은 다른 제공자를 쓴다.** 게임은 Claude(`ANTHROPIC_API_KEY`, dev 서버가 `.env.local`을 읽는다),
  봇은 Gemini 무료 티어를 직접 호출한다. 같은 키를 쓰면 한도·크레딧을 서로 갉아먹고,
  **무엇보다 측정 대상(게임 모델)과 측정 도구(봇)가 같은 모델이면 판별이 자기참조가 된다**
- **봇 프로세스에는 키를 직접 넣어야 한다** — `export $(grep GEMINI_API_KEY .env.local | xargs)`
- **분당 한도에 맞춰 스로틀한다** (봇 측 flash-lite = 15요청/분, `RPM=13`)
- **Claude 쪽 비용을 먼저 계산한다.** 완주 1회 12~15턴 × 약 $0.05 — 봇 4종이면 한 번에 $0.2 안팎이다
- **목업 폴백 횟수를 반드시 집계한다.** 폴백이 섞이면 LLM 측정이 아닌데 표에서는 구분되지 않는다
- **무난형 봇 대사에 맞장구만 넣지 않는다.** `"아하 그렇구나"` 류는 무성의형과 같은 등급이라
  판별이 무의미해진다. 기준 발화는 `src/engine/effort.test.ts`의 `plain` 목록에 고정돼 있다

## Won't — 이번 PoC에서 만들지 않는다

버린 게 아니라 **적어둔 것**이다. 제품화 단계에서 다시 꺼낸다.

### 하드 제외 (논의 없이 거절)

회원가입 · 로그인 · DB · 영속 저장(localStorage 포함) · 배포 인프라 작업 · 결제 ·
TTS/음성 · 이미지 생성 · 캐릭터 2명 이상 · 대화 저장/불러오기/이어하기

### 좋은 아이디어지만 범위 밖

| 아이디어 | 왜 지금은 아닌가 |
|---|---|
| 화별 선택지 분기 | 경우의 수가 급증해 모든 갈래의 대사 품질이 같이 나빠진다 ([#5](03-tradeoffs.md)) |
| AI가 먼저 연락 (푸시/비동기) | 매력적이지만 세션 밖 상태와 알림 인프라가 필요하다 |
| 4번째 시도 이상 심화 | 3번째에서 서사가 완결된다. 늘리면 재도전이 지루한 반복이 된다 |
| 캐릭터 커스터마이징 | 가설은 "리스크가 애착을 만든다"이지 "선택지가 재미를 만든다"가 아니다 |
| 대화 요약/기억 압축 | 총 12~15턴이라 필요 없다. 유한 서사의 부수 이득 |
| 트루엔딩 이후 일상 **대화** | 구간은 "연인이 되는 과정"까지다. 단, 연인이 된 다음 날은 고정 스크립트 에필로그로 **보여준다** (읽기 전용, 턴 없음) |
| 커플 사진 생성 (Kaze AI형) | 사진 생성기에는 연인이 없어 주제에서 오히려 멀어진다. Claude API는 이미지 생성 불가 — 별도 모델·업로드·스토리지가 필요하고 하드 제외 3건에 걸린다 ([#15](03-tradeoffs.md)) |
